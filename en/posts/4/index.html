Recursion and Divide-and-Conquer Algorithms

1. Basic Algorithmic Concepts

Break down large problems into small ones, simplify complexity, decompose a problem into multiple smaller subproblems of the same type, solve them, and finally merge the results to obtain the solution to the original problem.

For a problem to be solved, if its scale is large or the direct solving process is complicated, we can decompose it into multiple relatively small subproblems to solve. This is the basic idea of recursion. Divide-and-conquer algorithms are an application of recursion. Below, the author will briefly introduce their basic concepts and algorithmic ideas.

1.1 Recursion Algorithm

The advantage of recursive algorithms lies in their concise and easy-to-understand code, enabling bottom-up traversal and execution without using conventional loops. The disadvantage is lower space efficiency, as each recursive call allocates new space in memory; moreover, excessive recursion depth can lead to stack overflow issues.

1.2 Divide and Conquer Algorithm

Note: Divide-and-conquer is an application of recursion, but not all divide-and-conquer algorithms require recursive implementations.

The so-called "divide and conquer" means decomposing a large-scale problem that is complex to solve directly into multiple smaller-scale subproblems that can be solved directly using the same simple method. From this, we can see that the mindset of this algorithm is to repeatedly solve smaller subproblems, and then merge the answers of the subproblems into the answer to the large problem. The decomposition structure is shown in the figure below.

It is easy to see that the order of solving problems can follow a "bottom-up" approach. Therefore, recursive methods can be used to solve them.

Referring to the figure above, let \(n\) be the problem scale, and suppose each step divides into \(k\) subproblems until the subproblem scale is 1. Then the time complexity of merging these problems is \(O(n)\). Thus \(T(n)=kT(n/k)+O(n)\), and the overall time complexity can be reduced to \(O(n\log{n})\).

It should be noted that divide-and-conquer algorithms require the problem to meet the following conditions:

  • Each time the problem is divided, the division conditions cannot overlap (they must be mutually exclusive);
  • The union of the division conditions must cover all cases of the original problem.

2. Algorithm Applications

Here are several algorithmic applications of recursion and divide-and-conquer strategies.

2.1 Binary Search

Binary search is a typical application of divide-and-conquer algorithms. In a given sorted array, by comparing the target element with the middle element of the array, the sub-interval containing the target is determined. 2.3 Merge Sort and Quick Sort

2.3.1 Merge Sort

Merge sort is essentially a sorting method that divides first and merges later. If this occurs at every step of Partition(), its time complexity satisfies: \[ T(n)= \left\{ \begin{aligned} &O(1) &n\leqslant 1\\ &T(n-1)+O(n) &n>1 \end{aligned} \right. \] This recurrence relation gives: \(T(n)=O(n^2)\).

In the best case, where each pivot happens to be the median, each Partition() satisfies: \[ T(n)= \left\{ \begin{aligned} &O(1) &n\leqslant 1\\ &2T(\frac{n}{2})+O(n) &n>1 \end{aligned} \right. \] This recurrence relation gives: \(T(n)=O(n\log{n})\).

Ultimately, we find that the average time complexity of the quick sort algorithm is \(O(n\log{n})\).

2.4 Linear Time Selection

The problem linear time selection solves is finding the \(k\)-th smallest (or largest) element in a linearly orderable sequence. One approach is to sort all elements using a sorting algorithm and then locate the target element directly in \(O(1)\) time. But clearly, since we only need to find the \(k\)-th smallest (or largest) element, there is no need to sort the entire sequence. Algorithm Improvement:

In addition to the above method, there is another algorithm that can achieve sorting/selection in \(O(n)\) even in the worst case, generally referred to as Select (Median of Medians). Its steps are:

  1. Divide the \(n\) elements into \(\lceil n/5 \rceil\) groups, sort each group, and find its median;
  2. Recursively call the Select function to find the median of the \(\lceil n/5 \rceil\) medians (if \(\lceil n/5 \rceil\) is even, take the larger of the two middle elements), and use this element as the pivot for partitioning.
